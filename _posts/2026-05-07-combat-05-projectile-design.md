## 先给结论

抛射物是游戏中非常常见的用于触发效果的物体。

例如：

- 子弹
- 弓箭
- 回旋镖
- 飞刀
- 火球
- 追踪弹

从战斗系统角度看，抛射物本身不一定是最终结果。

它更像一个中间战斗对象：

```text
Skill 生成抛射物
-> 抛射物移动
-> 抛射物检测碰撞
-> 命中目标后触发 Effect
```

也就是说，抛射物负责移动、轨迹和命中，Effect 负责真正产生结果。

## 抛射物的定位

在前面的文章中，Skill 被定义为流程，Effect 被定义为具体结果。

抛射物则处在两者中间。

例如一个火球术：

```text
释放 Skill
-> 播放施法动作
-> 生成火球抛射物
-> 火球向目标飞行
-> 命中目标
-> 触发 DamageEffect
```

这里 Skill 不需要一直关心火球如何飞行，DamageEffect 也不需要关心火球从哪里飞来。

抛射物承担的是中间过程：

```text
从生成到命中之间发生了什么
```

因此，抛射物可以理解为：

> 一个带移动和碰撞逻辑的效果触发载体。

## 抛射物的特点

抛射物最核心的特点有两个：

```text
移动
特定轨迹
```

它不是立即生效的效果，而是在场上存在一段时间。

在这段时间里，它可能会：

- 向前移动
- 追踪目标
- 沿曲线飞行
- 返回释放者
- 穿透多个目标
- 命中后销毁
- 到达最大距离后消失

所以抛射物和普通 Effect 不同。

Effect 是一次性执行，而抛射物有一个短暂的生命周期。

```text
生成
-> 移动
-> 碰撞检测
-> 命中或结束
-> 销毁
```

## 常见字段

抛射物的实现思路和 Buff 有点类似。

它并不一定需要一开始就设计得非常复杂，而是根据需求逐步增加字段。

常见字段包括：

- 移动速度
- 碰撞尺寸
- 碰撞次数
- 最大飞行距离
- 最大存在时间
- 移动轨迹
- 是否追踪目标
- 是否穿透
- 是否命中后销毁
- 碰撞时触发的 Effect
- 结束时触发的 Effect

例如一个普通子弹可能只需要：

```text
移动速度
碰撞尺寸
命中 Effect
```

一个回旋镖则可能需要：

```text
移动轨迹
返回逻辑
多次碰撞
碰撞目标记录
命中 Effect
```

一个追踪弹可能需要：

```text
目标对象
追踪速度
转向速度
最大追踪时间
命中 Effect
```

字段本身并不复杂，关键是要明确每个字段服务于哪种抛射物行为。

## 移动轨迹

抛射物的表现差异，很多时候来自移动轨迹。

常见轨迹包括：

- 直线
- 曲线
- 抛物线
- 追踪
- 回旋
- 环绕
- 固定区域移动

不同轨迹对应不同实现方式。

例如直线子弹只需要方向和速度。

```text
当前位置 += 方向 * 速度 * 时间
```

追踪弹则需要持续调整方向。

```text
计算目标方向
-> 根据转向速度修正当前方向
-> 沿新方向移动
```

回旋镖则需要区分飞出和返回两个阶段。

```text
飞向目标方向
-> 到达距离或时间
-> 返回释放者
```

因此，移动轨迹最好不要写死在单个抛射物逻辑里。

更适合的方式是把轨迹当成配置或策略，让不同抛射物选择不同移动方式。

## 碰撞和命中

抛射物最终通常需要通过碰撞来触发效果。

碰撞逻辑要回答几个问题：

- 碰撞范围有多大
- 可以命中哪些目标
- 是否能命中同一目标多次
- 最多能命中几次
- 命中后是否销毁
- 是否可以穿透
- 是否需要记录已命中过的目标

例如普通子弹：

```text
命中 1 个目标
-> 触发 DamageEffect
-> 销毁
```

穿透子弹：

```text
命中目标
-> 触发 DamageEffect
-> 记录目标
-> 继续飞行
-> 达到碰撞次数后销毁
```

范围抛射物：

```text
到达目标点
-> 搜索范围内敌人
-> 对每个目标触发 Effect
-> 销毁
```

可以看到，抛射物的碰撞并不只是物理碰撞，而是战斗规则的一部分。

## 抛射物和 Effect 的关系

抛射物不应该直接写死具体战斗结果。

更稳定的方式是：

```text
抛射物负责命中
Effect 负责结果
```

例如：

```text
火球命中
-> DamageEffect

冰箭命中
-> DamageEffect
-> AddBuffEffect

治疗弹命中友方
-> HealEffect
```

这样同一个抛射物逻辑可以复用不同 Effect。

一个直线飞行的抛射物，可以触发伤害，也可以触发治疗，还可以触发添加 Buff。

抛射物只需要在命中时把上下文传给 Effect。

```text
释放者
目标
抛射物位置
命中点
技能参数
```

Effect 再根据上下文执行具体逻辑。

## 抛射物的变种

抛射物不一定只表现为“一个飞行物体”。

从设计思路上看，只要它承担了“检测目标并触发 Effect”的职责，都可以放进相似的抽象里。

常见变种包括：

- AOE：在一个范围内搜索目标并触发 Effect
- 固定区域：在场上保留一段时间，持续检测进入区域的目标
- 射线：把移动过程压缩成一次路径检测
- 延迟爆炸点：先生成一个位置，等待一段时间后触发范围效果
- 持续伤害区域：在生命周期内按规则重复触发 Effect

这些表现形式不同，但底层关注点是类似的：

```text
如何确定目标
何时触发 Effect
是否需要持续存在
是否需要限制命中次数
```

因此，抛射物系统不一定只服务于子弹、弓箭、火球这类飞行物，也可以扩展到范围、区域、射线等效果载体。

## 抛射物的生命周期

抛射物虽然不像 Buff 那样是长期状态，但也有自己的生命周期。

可以抽象为：

```text
创建
-> 初始化参数
-> 开始移动
-> 碰撞检测
-> 命中目标
-> 触发 Effect
-> 达到结束条件
-> 销毁或回收
```

结束条件可以有很多种：

- 命中目标
- 达到最大距离
- 达到最大时间
- 碰撞次数用完
- 目标消失
- 释放者死亡
- 场景切换

这些规则如果不提前明确，就容易出现抛射物残留、重复命中、目标丢失后行为异常等问题。

## 总结

抛射物是用于承载移动、轨迹和碰撞逻辑的战斗对象。

它的核心价值不是直接产生结果，而是把 Skill 和 Effect 之间的过程表达出来。

可以概括为：

```text
Skill 生成抛射物
抛射物负责移动和命中
Effect 负责产生结果
```

抛射物的设计重点包括：

- 移动速度
- 移动轨迹
- 碰撞尺寸
- 碰撞次数
- 命中规则
- 生命周期
- 命中时触发的 Effect

因此，抛射物不应该被设计成某个技能的附属逻辑，而应该作为一个独立的战斗对象来管理。
