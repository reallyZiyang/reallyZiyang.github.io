## 先给结论

被动技能是技能描述中特定情况下才会触发的能力。

例如：

- 使用多次技能后，下一次伤害技能附带眩晕
- 攻击、暴击、击杀后获得怒气
- 释放技能或被技能命中后，缩短某个被动技能的冷却时间
- 生命值低于一定比例时触发护盾或治疗

这类技能和普通主动技能不同。

它不是释放技能时立即进入一段流程，而是在战斗过程中等待某个条件出现。

因此，被动技能的重点不是“执行什么效果”，而是：

```text
什么时候触发效果
```

真正产生结果的部分仍然应该交给 Effect。

被动技能更适合被拆成：

```text
触发条件
-> 触发器监听战斗事件
-> 条件满足
-> 执行 Effect
```

## 和 Buff 的差异

Buff 和被动技能看起来有些相似。

它们都可能持续存在，也都可能在某些条件下触发效果。

但两者的核心驱动力不同。

Buff 更偏时间驱动：

```text
添加 Buff
-> 持续一段时间
-> 按间隔触发 Effect
-> 到期移除
```

被动技能更偏事件驱动：

```text
监听事件
-> 事件发生
-> 检查条件
-> 条件满足后触发 Effect
```

例如“每 2 秒造成一次伤害”更像 Buff。

“造成 4 次伤害后，下一次伤害附带额外效果”更像被动触发器。

两者并不是互斥关系。

有些设计可以用 Buff 实现，也可以用被动触发器实现。

区别在于抽象重点不同：

```text
Buff 关心持续时间和生命周期
触发器关心事件和触发条件
```

## 常见触发条件

被动技能的触发条件通常来自战斗事件。

常见条件包括：

- 击杀目标
- 造成伤害
- 受到伤害
- 暴击
- 释放特定技能
- 命中特定目标
- 生命值低于一定比例
- 进入战斗或脱离战斗
- 单位死亡或重生

这些条件可以继续组合出更复杂的规则。

例如：

```text
造成伤害 4 次后触发
```

```text
使用指定技能后触发
```

```text
击杀目标后触发，但有最大触发次数限制
```

```text
被敌方英雄技能命中时触发，被野怪命中时触发另一套规则
```

可以看到，被动技能的复杂度通常不在 Effect 本身，而在触发条件的组合。

## 触发器的定位

触发器可以理解为被动技能中的条件监听对象。

它不负责造成伤害、回血、添加 Buff，也不负责播放表现。

它只负责一件事：

```text
判断某个条件是否成立
```

当条件成立时，触发器通知外层执行 Effect。

也就是说：

```text
Trigger 负责条件
Effect 负责结果
```

例如“造成 4 次伤害后触发眩晕”可以拆成：

```text
造成伤害触发器
-> 记录造成伤害次数
-> 达到 4 次
-> 触发 AddBuffEffect
```

“击杀目标后获得怒气”可以拆成：

```text
击杀触发器
-> 监听击杀事件
-> 触发 AddValueEffect
```

这样设计后，被动技能就不会和具体战斗结果绑定死。

同一个“击杀触发器”可以用于回怒，也可以用于回血、刷新技能、添加 Buff。

## 实现思路

触发器的实现可以结合 Effect 和 Buff 的特点。

它应该尽量保持：

- 无状态或少状态
- 独立
- 可进入
- 可退出
- 退出时可完整清理

这里的“无状态”不是完全没有数据，而是不要保存不必要的外部状态。

触发器只保留判断条件所需的最小数据。

例如：

- 当前计数
- 最大触发次数
- 指定技能 ID
- 指定 Effect ID
- 冷却时间
- 是否已经触发

触发器进入时注册事件：

```text
进入
-> 监听造成伤害事件
```

触发器退出时取消注册事件：

```text
退出
-> 移除造成伤害事件监听
```

事件发生后再检查条件：

```text
造成伤害事件发生
-> 判断来源是否匹配
-> 判断计数是否满足
-> 判断次数限制是否满足
-> 触发 Effect
```

这样的结构可以避免触发器和战斗主流程互相污染。

战斗主流程只负责抛出事件，触发器自己决定是否响应。

## 生命周期

触发器虽然是事件驱动，但仍然需要明确生命周期。

它至少要回答几个问题：

- 什么时候开始监听
- 什么时候停止监听
- 触发后是否继续存在
- 是否有触发次数上限
- 是否需要冷却
- 所属单位死亡后是否移除
- 技能或 Buff 被移除后是否取消监听

如果生命周期没有处理清楚，就容易出现一些隐蔽问题。

例如：

- 单位死亡后触发器仍然在监听事件
- Buff 移除后被动技能仍然生效
- 同一个触发器被重复注册，导致效果触发多次
- 触发器内部计数没有重置，导致下一次添加时状态异常

因此，触发器必须成对处理进入和退出。

可以概括为：

```text
OnEnter 负责注册
OnExit 负责反注册
```

只要退出时能把注册过的事件、临时状态和外部影响清理干净，就可以避免被动技能残留在战斗系统里。

## 总结

被动技能是技能描述中特定条件下才会触发的能力。

它的核心不是结果，而是触发条件。

可以概括为：

```text
战斗事件发生
-> Trigger 判断条件
-> 条件成立
-> 执行 Effect
```

Buff 更偏时间驱动，被动技能更偏事件驱动。

触发器的设计重点包括：

- 监听什么事件
- 检查什么条件
- 触发什么 Effect
- 是否需要计数
- 是否需要次数限制
- 什么时候注册和反注册
- 退出时能否完整清理

只要把触发条件和具体效果拆开，被动技能就可以被组织成一套独立、可组合、可清理的战斗规则。
