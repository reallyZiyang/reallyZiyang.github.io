## 先给结论

回合制战斗编辑器的核心不是“编辑一场真实战斗”，而是“编辑一份可以驱动战斗播放的战报”。

上一章提到，回合制战斗可以拆成：

```text
战报驱动
命令序列播放
```

那么编辑器要做的事情就是围绕这两点展开：

```text
编辑战报数据
-> 重建命令序列
-> 播放或跳转到指定回合
-> 检查表现是否符合预期
```

因此，回合制战斗编辑器更像一个战报调试工具。

它不需要重新实现一套战斗逻辑，而是复用正式战斗中的战报结构和播放流程。

## 编辑器的功能

从功能上看，回合制战斗编辑器主要包含几类操作。

第一类是战报操作。

例如：

- 创建战报
- 读取战报
- 修改战报
- 保存战报
- 插入行动
- 复制行动
- 粘贴行动

战报本身是一份结构化数据。

编辑器只负责让这份数据更容易被查看和修改。

第二类是战斗数据的增删查改。

例如：

- 修改行动单位
- 修改目标单位
- 修改行动类型
- 修改技能 ID
- 添加战斗事件
- 删除战斗事件
- 修改事件参数
- 修改单位属性和 Buff

这些数据最终都会影响战斗播放。

例如修改一条伤害事件的数值，播放时飘字、血条和死亡表现都会跟着变化。

第三类是调试播放。

例如：

- 播放当前回合
- 暂停战斗
- 恢复战斗
- 跳过战斗
- 调整战斗速度
- 跳转到指定行动

这些能力的意义是快速验证数据变化后的表现。

编辑器不是单纯改 JSON，而是要能让修改后的数据立刻进入战斗流程。

## 即时生效

编辑器最重要的体验是即时生效。

当战报数据被修改后，需要重新生成命令序列。

因为命令序列是由战报中的行动构建出来的。

可以理解为：

```text
修改 TurnContext
-> 重新构建 Command
-> 重新定位到当前回合
-> 播放当前命令
```

例如修改当前行动的技能 ID 后，原来的命令已经不能代表最新数据。

这时需要清空旧命令序列，再根据新的战报重新构建。

这样编辑器才能保证：

```text
看到的数据
播放的表现
是一致的
```

如果没有即时重建命令序列，编辑器就容易出现“数据已经改了，但播放还是旧表现”的问题。

## 跳转和回滚

回合制战斗编辑器需要支持跳转。

例如从第 10 个行动跳回第 3 个行动，或者从第 2 个行动直接跳到第 8 个行动。

这个能力的关键不是命令序列，而是战斗状态如何还原。

因为回合制战斗状态是随着行动不断推进的。

例如：

```text
第 1 次行动后，角色 A 扣血
第 2 次行动后，角色 B 获得 Buff
第 3 次行动后，角色 A 死亡
```

如果直接把索引改到第 2 次行动，但不处理单位状态，就会出现当前状态和当前回合不匹配的问题。

更稳定的方式是：

```text
回到初始单位状态
-> 从第 1 条行动开始重新应用战斗事件
-> 一直推进到目标行动之前
-> 得到目标行动开始前的状态
```

也就是说，跳转本质上不是“移动播放指针”这么简单。

它还要把动态状态回滚到正确位置。

这里的关键是每个 TurnContext 都能根据自己的 BattleEvent 更新单位状态。

可以抽象为：

```text
TurnContext
-> 遍历 BattleEvent
-> 将事件应用到 UnitContext
-> 得到行动后的单位状态
```

当需要跳到某个行动时，只要从初始状态开始，依次执行前面行动的状态更新，就可以还原出目标位置的正确状态。

这种方式的好处是可预测。

不管从哪里跳到哪里，最终状态都只由战报数据决定。

## 可播放和可回滚

编辑器中的“可播放”和“可回滚”对应两套能力。

可播放依赖命令序列。

```text
当前行动
-> 构建命令
-> 执行命令
-> 播放表现
```

可回滚依赖战报状态重算。

```text
初始状态
-> 应用前面所有行动的 BattleEvent
-> 得到当前行动前的状态
```

两者结合后，编辑器就可以做到：

- 任意选择一个行动
- 自动还原到该行动前的状态
- 从该行动开始播放表现
- 修改数据后重新播放验证

这也是回合制战斗编辑器最有价值的地方。

它不只是一个数据面板，而是一个可以反复验证表现的战斗调试环境。

## 数据和表现分离

回合制战斗编辑器成立的前提，是数据和表现已经分离。

战报数据只描述结果。

例如：

```text
谁行动
对谁释放技能
产生哪些 BattleEvent
```

表现层只负责消费这些数据。

例如：

```text
播放动作
在关键帧消费事件
显示飘字
更新血条
播放受击或死亡表现
```

这样编辑器才可以通过“单纯编辑数据”来驱动表现变化。

例如：

- 改伤害数值，飘字和血条变化
- 改目标单位，受击对象变化
- 改技能 ID，播放的动作变化
- 添加 Buff 事件，Buff 表现变化

如果表现逻辑写死在技能或动画里，编辑器就很难做到这种数据驱动。

因为改战报数据并不能完整影响表现。

更稳定的方式是：

```text
数据描述战斗结果
命令组织播放流程
表现根据数据执行
```

## 总结

回合制战斗编辑器主要解决的是战报调试问题。

它的核心能力包括：

- 战报创建、读取、修改和保存
- 战斗数据的增删查改
- 修改后即时生效
- 指定回合播放
- 指定回合跳转
- 根据战报回滚状态

其中最关键的是两点：

```text
通过战报数据驱动表现
通过 TurnContext.UpdateUnitContext 实现状态跳转和回滚
```

只要战报结构、命令序列和状态更新规则足够清晰，编辑器就不需要写大量特殊逻辑。

它只需要编辑数据、重建命令、跳转状态、播放表现，就能成为一套稳定的回合制战斗调试工具。
